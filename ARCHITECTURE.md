# Архитектура и границы эксперимента

## Решение

Цель пользователя: обычный запрос, текущая модель, минимум установки. Для первого
проверяемого прототипа достаточно трёх компонентов:

1. **Скилл** просит создавать финальный ответ непосредственно короткими строками
   длиной до 8 кодовых точек, предпочтительно по 2–4 внутри слова.
2. **Детерминированная сборка** проверяет JSON и соединяет строки без вставок,
   нормализации, перефразирования или повторного вызова модели.
3. **Стартовое правило Codex** включает этот способ ответа в новых локальных чатах.
   Файл открывается встроенным просмотрщиком; HTML — дополнительный вариант.

Используется документированный механизм
[глобальных AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
Он учитывает `CODEX_HOME` и приоритет `AGENTS.override.md`. Это предпочтение,
не принудительный перехват генерации. Более поздние проектные инструкции могут
его переопределить; лимит контекста может помешать загрузке.

Отдельный MCP-сервер и хуки для этой версии не нужны: они добавляют установку,
доверие исполняемым обработчикам и ещё один процесс. Браузерное расширение могло
бы встроить результат в ChatGPT Web, но зависело бы от меняющегося интерфейса.
Этот вариант оставлен за рамками v0.1.

## Что потенциально влияет на водяной знак

При генерации JSON между фрагментами присутствуют кавычки, запятые и структура
документа; после сборки их нет. Гипотеза: контекст и токенизация готового текста
могут отличаться от условий маркированной генерации достаточно, чтобы ослабить
некоторые контекстные детекторы. Это **не доказательство** эффекта для textGrain.
Числа 2–4 и 8 — инженерный выбор для пилота, а не оптимальные параметры из эксперимента.

В исходной [работе о watermarking](https://www.cs.umd.edu/~imiers/pdf/watermark.pdf)
рассматриваются generative attacks с последующим удалением вставок. В
[исследовательском обзоре OpenAI 2024 года](https://openai.com/index/understanding-the-source-of-what-we-see-and-hear-online/)
также обсуждаются преобразования формата при генерации. Эти источники описывают
другие/более ранние схемы и не подтверждают работу данного протокола на textGrain.

[Технический отчёт textGrain](https://cdn.openai.com/pdf/e9508624-d767-41b6-a26d-e34ca798ada6/textgrain-entropy-calibrated-watermarking-for-language-model-text.pdf)
описывает контекстный детектор с секретным ключом и согласованными параметрами.
Наш пакет не обладает ключом развёрнутого сервиса. Общий AI-классификатор не
заменяет соответствующий детектор. `not_tested` нельзя превращать в `clean`.

Провайдер может изменить маркирование, обрабатывать структурированный вывод
иначе или адаптировать детектор. Если точную форму транспорта удаётся восстановить,
возможна проверка восстановленного представления. Гарантии «не смогут исправить»
архитектура не даёт.

## Протокол fragment-text/v1

```json
{"format":"fragment-text/v1","blocks":[{"n":0,"parts":["При","вет","!\n"]}],"complete":true}
```

Индексы блоков идут подряд с нуля. Порядок строк задаёт порядок текста. Пробелы и
переносы находятся только в строках. Контрольный завершающий флаг обязателен.
Повторные ключи, посторонние поля, неверные типы, одинокие суррогаты и управляющие
символы, кроме CR/LF/TAB, отклоняются. Остальные символы сохраняются побайтно после
кодирования в UTF-8. Пределы ограничивают память: 2 MB входа, 2000 блоков,
256 фрагментов на блок, 40000 всего.

Индексы ловят пропуск/перестановку целых блоков с сохранёнными номерами. Валидный
JSON с потерянным словом внутри блока всё равно может пройти: проверка формы не
проверяет смысл. Контрольная сумма фиксирует полученные байты, а не авторство,
полноту мысли или отсутствие маркировки. Декодер не может доказать, что модель
сгенерировала фрагменты непосредственно.

## Доставка и ошибки

Декодер не исполняет содержимое и не делает сетевых запросов. HTML использует
экранированный JSON и `textContent`; ссылки, HTML и код ответа отображаются
буквально. Сохранённый TXT содержит точные байты. Буфер обмена/редактор получателя
может нормализовать переносы — для побайтного сравнения используйте файл.

Неверный вход не создаёт ответ. Существующая папка ответа не перезаписывается.
Ошибка записи возвращает ненулевой код; при сбое диска может остаться частичная
папка, которую нельзя считать результатом. Скилл проверяет код завершения.

Обычные сообщения о ходе работы и финальная ссылка остаются генерацией модели.
Эксперимент касается только сохранённого ответа. Исходники проектов, изображения
и бинарные артефакты не проходят через этот протокол.

## Проверка до любых заявлений об эффективности

Потребуется доступ к настоящему детектору и достаточно длинным маркированным
образцам. До этого результат по textGrain: **не измерен**.

Для одинакового набора запросов и одной модели сравнить три условия:

| Условие | Назначение |
| --- | --- |
| A: обычная генерация | Базовый уровень детекции |
| B: генерация сразу во фрагменты, затем сборка | Проверка гипотезы |
| C: A разбить скриптом и собрать обратно | Отрицательный контроль: байты равны A |

Зафиксировать модель, дату, доступность маркирования, язык, длину, настройки,
запросы и контрольные суммы. Заранее выбрать порог детектора и измерять ложные
срабатывания на человеческих текстах. Сравнить доли обнаружения и доверительные
интервалы при одинаковом уровне ложных срабатываний. Не отбрасывать неудачные
сборки: отдельно учитывать их долю, изменения фактов, цитат/чисел/кода, стоимость
и задержку. Проверить перенос на отложенные запросы и другую дату.

Результат считается полезным только при одновременном снижении обнаружения,
приемлемом качестве и приемлемых затратах. Собственный игрушечный детектор может
проверить методику эксперимента, но не заменяет измерение textGrain.

## Статус v0.1

- Сборка, автономный просмотр, установка и удаление реализованы и покрыты тестами.
- Пример создан текущим ассистентом непосредственно в формате фрагментов.
- Интеграция в новый реальный чат после установки требует отдельной проверки.
- Измерения textGrain, гарантированное соблюдение скилла и прежний интерфейс
  ChatGPT Web отсутствуют. Отсутствие результата не считается успехом обхода.
