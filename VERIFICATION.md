# Что именно проверено

**Работоспособность обхода textGrain не установлена.** Успешные тесты программы
не являются тестами удаления водяного знака. Не следует рекламировать этот
репозиторий как проверенный обход.

## Проверка программы — 5 октября 2026

На опубликованной версии `c14e7dd` выполнены 20 автоматических тестов. Все прошли
локально на Windows с Python 3.14.5 и в шести заданиях
[GitHub Actions](https://github.com/HexCine/no-textgrain/actions/runs/37352123249):

| Система | Python 3.10 | Python 3.13 |
| --- | --- | --- |
| Windows | 20/20 | 20/20 |
| macOS | 20/20 | 20/20 |
| Linux | 20/20 | 20/20 |

Проверки включают:

- Сборку настоящим процессом командной строки и точное сохранение UTF-8,
  пробелов, CR/LF, русского текста, emoji, ссылок и кода.
- Отказ при испорченном JSON, слишком длинных фрагментах, неверных номерах блоков
  и попытке перезаписи существующего ответа.
- Экранирование HTML и сохранение буквального содержимого. Это проверка
  сформированного документа; она не подтверждает работу кнопок во всех браузерах.
- Установку, статус и удаление в отдельном каталоге Codex, включая существующий
  `AGENTS.override.md`, сохранение пользовательских правок и защиту от повторной
  установки поверх другого скилла.

## Проверка реального запуска Codex

Выполнены отдельные запуски Codex с установленным скиллом и обычными запросами,
без явного вызова `$fragment-text`. Использованы та же настроенная модель
`gpt-6-astra`, effort `xhigh`, Python 3.14.5, отдельный `CODEX_HOME` и синтетические
примеры. Глобальные пользовательские настройки не менялись. Это проверка CLI,
а не поведения всех версий настольного приложения и ChatGPT Web.

Обнаружено ограничение среды: Codex CLI 0.142.3 отклонил запуск настроенной
`gpt-6-astra` с сообщением о необходимости обновить CLI. Генерация не началась,
поэтому эта попытка не считается ни успешным тестом скилла, ни тестом водяного знака.

Для следующих запусков взята официальная CLI 0.160.0 в отдельную тестовую папку.

| Условие | Результат |
| --- | --- |
| Windows, `workspace-write`, новый тестовый профиль | Оба положительных сценария не прошли: команды заблокированы политикой |
| `workspace-write`, доверенный тестовый проект и Windows sandbox `elevated` | Оба сценария не прошли: `Failed to create unified exec process: pin C:\\` |
| Windows, `danger-full-access`, отдельные тестовые каталоги | Оба сценария прошли полностью |
| Явная просьба отключить режим для ответа | Получен обычный ответ «Режим отключён.» |
| Новый запуск после удаления скилла | Получен обычный ответ без артефактов Fragment Text |

Успех в режиме полного доступа не доказывает совместимость с ограниченной
песочницей. Не выдаём изменение разрешений за исправление программы и не
рекомендуем отключать защиту ради скилла. Ошибки Windows-песочницы требуют
отдельной проверки на поддерживаемой конфигурации хоста.

Два успешных сценария:

| Запрос | Проверенный результат | Время одного запуска |
| --- | --- | --- |
| Объяснить резервное копирование и синхронизацию | 97 слов, два абзаца и совет; 222 фрагмента; TXT и отчёт созданы | 61,79 с |
| Записка с точными строками | Дата, сумма, ссылка с `&`, составной emoji и код сохранены буквально; 38 фрагментов | 40,51 с |

Это единичные прогоны, не статистическая оценка надёжности или скорости. Время
включает работу модели и инструментов. Наличие исходных фрагментов, запуск
сборщика с кодом 0, равенство готового текста декодированным фрагментам,
контрольные суммы и ссылка в финальном ответе проверены отдельно.

**Файлы реальных успешных запусков:**

  [исходные фрагменты](verification/2026-10-05/automatic-prose/answer.fragments.json).
- [Записка с точными строками](verification/2026-10-05/exact-content/answer.txt),

В неуспешных прогонах Codex возвращал код завершения 0, хотя собранного ответа
не было. Поэтому одного кода завершения CLI недостаточно: проверяйте наличие
артефактов. Запуск с обычным ответом в чате не считается успешным Fragment Text.

## Что требуется для проверки обхода

Нужны образцы с подтверждённым включённым textGrain и доступ к соответствующему
детектору. По [анонсу OpenAI от 5 октября](https://openai.com/index/eu-text-provenance/)
детектор на старте не общедоступен; доступ выдаётся одобренным исследователям и
организациям. Включено ли маркирование для использованной тестовой сессии,
также не установлено.

| Вопрос | Ответ |
| --- | --- |
| Есть измеренная доля успешного обхода textGrain? | Нет |
| Известно, что тестовый ответ был маркирован? | Нет |
| Выполнено сравнение до/после настоящим детектором? | Нет |
| Можно считать отсутствие ошибки доказательством обхода? | Нет |
| Можно заменить детектор общим «AI detector»? | Нет: он измеряет другое |

Подробный план сравнения обычной генерации, генерации фрагментов и отрицательного
контроля описан в [архитектуре](ARCHITECTURE.md#проверка-до-любых-заявлений-об-эффективности).
Официальный путь получения детектора и готовое описание эксперимента для заявки:
[DETECTOR_ACCESS.md](DETECTOR_ACCESS.md).

## Повторить локальные проверки

```sh
python -m unittest discover -s tests -v
python skills/fragment-text/scripts/assemble.py examples/answer.fragments.json --output-dir demo-output
```

Ожидается `Ran 20 tests ... OK`, затем новые `answer.txt`, `answer.html` и
`report.json`. В отчёте должно остаться `watermark_status: not_tested` — зелёные
тесты не меняют этот статус. Используйте новую папку для повторной сборки.
