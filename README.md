# Fragment Text — эксперимент для Codex

Та же модель генерирует ответ короткими фрагментами. Локальный скрипт соединяет
их и показывает готовый текст. Без Ollama, другой модели, ключей API, сервера,
Docker и сторонних Python-пакетов.

**Подтверждённого обхода textGrain здесь пока нет.** Сборка текста работает;
удаление водяного знака не проверено. Не используйте зелёный статус тестов как
доказательство обхода. Обещаний «100%», «навсегда» и «невозможно исправить» нет.

| Что проверяем | Результат |
| --- | --- |
| Сборка текста и установка/удаление | 20 тестов прошли на Windows, macOS и Linux |
| Новый запуск Codex → автоматический скилл → готовый файл | 2/2 в Codex CLI 0.160.0 + Astra на Windows с полным доступом |
| Такой же запуск в Windows-песочнице | Не прошёл в тестовой среде: локальные команды заблокированы/не запускаются |
| Удаление или ослабление textGrain | **Не проверено: нет доступа к детектору** |
| Прежний интерфейс ChatGPT Web | Не реализован |

Воспроизводимые проверки, ограничения и результаты реальных запусков:
**[VERIFICATION.md](VERIFICATION.md)**.

## Установка

Нужны локальный Codex и Python 3.10+. Скачайте репозиторий или ZIP, распакуйте,
откройте терминал в папке и выполните:

```sh
python setup.py install
```

На macOS/Linux команда интерпретатора может называться `python3`.
Установщик копирует скилл в каталог Codex и добавляет короткое правило в активный
глобальный `AGENTS.md` (либо существующий `AGENTS.override.md`). Исходные инструкции
сохраняются в резервной копии. Это изменяет предпочтение для **всех новых локальных
чатов Codex**. Модель, серверные настройки и разрешения не меняются.

Начните новый чат и задайте обычный вопрос. Codex должен собрать ответ и открыть
его как файл; в сообщении останется ссылка. Автовключение — инструкция модели:
на неё могут повлиять ограничения хоста, более приоритетные инструкции и настройки
загрузки контекста. Проверяйте первый ответ после установки. Прозрачная замена
каждого сообщения в обычном ChatGPT Web этим пакетом **не реализована**.

Для работы необходимы разрешённые локальные команды и запись файлов. При их
запрете модель может ответить обычным текстом, даже если Codex завершился без
ошибки. Признак успешного прохождения именно нашего процесса — созданные
`answer.txt` и `report.json` со ссылкой на ответ. Это всё ещё не признак обхода
водяного знака. Мы не рекомендуем отключать защиту ради скилла: совместимость
с Windows-песочницей в нашем изолированном тесте не подтверждена.

Для установки только скилла, без режима по умолчанию:

```sh
python setup.py install --manual
```

Тогда вызывайте `$fragment-text` в нужном чате. Для разового отключения попросите
«ответь обычным текстом в чате». Проверка установки и полное отключение:

```sh
python setup.py status
python setup.py remove
```

Удаление убирает только неизменённый собственный блок инструкций и переносит скилл
в резервную копию. Пользовательские дополнения сохраняются. Начните новый чат.
Для обновления сначала `remove`, затем `install` из новой версии.

## Что происходит с ответом

```text
Обычный запрос → текущая модель → короткие JSON-фрагменты
                                   ↓
                            локальная сборка
                                   ↓
                      answer.txt + просмотр с копированием
```

Ответ показывается из файла, чтобы модель не генерировала его повторно. В HTML
есть кнопки копирования и сохранения; Markdown отображается как исходный текст.
Скрипт не исправляет орфографию, не меняет слова и не удаляет Unicode-символы.
Отчёт хранит контрольные суммы и явное `watermark_status: not_tested`.
Декодер не обращается в сеть. Обычная генерация продолжает идти через ваш Codex.

У схемы есть цена: больше выходных токенов и времени, нет обычного потокового
ответа в пузыре чата. Ускорение, экономия и ослабление водяного знака не измерены.
Если важен абсолютно прежний интерфейс без файлов, этот прототип пока не решает
такую задачу.

## Быстрая проверка без установки

```sh
python skills/fragment-text/scripts/assemble.py examples/answer.fragments.json --output-dir demo-output
python -m unittest discover -s tests -v
```

Откройте `demo-output/answer.html`. При повторном запуске укажите новую папку:
скрипт не перезаписывает прежние ответы. Тесты проверяют сборку, ошибки, Unicode,
изоляцию HTML и сохранность настроек; **они не измеряют водяной знак**.

## Почему это пока гипотеза

В [анонсе OpenAI](https://openai.com/index/eu-text-provenance/) textGrain описан как
статистическое маркирование при генерации; публичного универсального детектора
на старте нет. Очистка пробелов и «невидимых символов» не отключает такой механизм.
Форматирование *во время* генерации исследовалось как способ ослабления некоторых
схем, но переносимость результата на textGrain не доказана. Подробности,
ограничения и план проверки — в [ARCHITECTURE.md](ARCHITECTURE.md).
